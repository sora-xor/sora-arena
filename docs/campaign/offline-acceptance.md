# Offline campaign progression acceptance

Run `python3 scripts/unreal/test_campaign_progression.py` from the repository root. It reads the eight authored chapters from `Content/Data/catalog.json`, generates a temporary C++ fixture, and compiles `campaign_progression_driver.cpp` against `SoraCampaignRules.h`. The same rules header gates checkpoints, defeats, production-site interactions, final-boss admission, exits, chapter advance, and liberation in `ASoraGameMode`.

The host driver walks every chapter's defeat count and three production sites. At each milestone it tests prerequisite and defeat gates, copies and validates the local checkpoint value, rejects premature completion and malformed checkpoints, then advances to the next chapter. In the eighth chapter it requires the collector spawn gate at 17 of 18 defeats and liberation only after the final site and exit. The Python side checks that every authored Japanese dialogue cue and speaker has a nonempty English counterpart; it does not test subtitle rendering or voice.

This is a **rules and content acceptance test**, not a completed Unreal campaign run. It does not instantiate `UWorld`, call `ASoraWorldBuilder::ActivateNearest`, serialize `USoraSaveGame` with `SaveGameToSlot`, exercise collision or boss attacks, render HUD subtitles, or measure mission duration. Those APIs require a UE 5.8.2 editor/runtime, which is not installed on this machine. An in-engine follow-up must script player movement, each actual site interaction and enemy defeat, save-slot teardown/reload at chapter and boss milestones, then verify the final liberation state and bilingual HUD cues. Combat readability, 6–8 hour pacing, cinematics, and visual quality require separate playtests and performance captures.
