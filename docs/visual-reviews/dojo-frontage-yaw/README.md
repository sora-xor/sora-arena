# Estate Dojo frontage yaw, same-package Mac A/B

**Recommendation: retain the current main placement, `S>0 ? 180° : 0°`, for the Dojo.** At both near-road cameras, the current yaw shows the four shōji lattice bays, engawa, and entry steps. Flipping the Dojo 180° shows its four broad rear plaster panels. This is high-confidence evidence for the Dojo frontage orientation in the packaged UE **5.8.3** diagnostic; it is not a UE 5.8.2 release qualification or an overall visual-quality claim. No production C++ was changed.

The authored Blender mesh has its public frontage at **local −Y**: `Shoji_Paper` is at `y = −2.751 m`, the lattice just ahead at approximately `−2.795 m`, and the steps extend from `−3.66 m` toward `−3.98 m`. `Rear_Plaster` is at `+2.68 m`. The FBX was exported with `axis_forward="-Y", axis_up="Z"`; Unreal's import task has no explicit import rotation. The packaged result establishes the imported Dojo's effective frontage as **Unreal local +Y**: the north row at `Y=+1800 cm` shows the shōji when yaw 180° maps local +Y toward the central road (world −Y), while the south row at `Y=−1800 cm` shows it when yaw 0° maps local +Y toward the road (world +Y). This agrees with the source manifest's placement note and the current main `SoraWorldBuilder.cpp` yaw. The isolated UE5.8.3 checkout had an older opposite default, so the test-only selector explicitly reproduced **current main** yaw for the control; `-SoraDojoFrontageFlip` reversed Dojo art only. Kura orientation was not tested.

One Mac Development package was built, cooked, and staged using the isolated UE5.8.3 worktree. Each variant used a fresh process of that **same package**, 1280×720, the same lighting/settings, and fixed cameras. The north camera was `(−2000, 654, 154.15) cm` at pitch `12°`, yaw `90°`; the south camera was `(−2000, −654, 154.15) cm` at pitch `12°`, yaw `−90°`; both used 65° FOV. Logs show all six Dojo instances at north/south row yaw `180°/0°` for current and `0°/180°` for flip. The comparison frames are unedited:
