# Localhost P2P evidence transport research

`arena_core::localhost_transport` exchanges signed evidence over real UDP sockets bound to loopback addresses. It only accepts an **offline admission** (zero XOR bond) and one exact, pre-admitted peer address. Both peers must already have the same authenticated `Context`, `Config`, ordered participant roster, and separate `DurableSession` journals.

The initiator sends an Ed25519-signed ephemeral X25519 offer. The responder verifies it and syncs the accepted offer into its evidence journal, then syncs a receipt file before sending its signed answer. Each peer derives separate directional AEAD keys. Subsequent `WireFrame` certificates, individual reveals, and checkpoints are signed, encrypted, fragmented into at-most-1,200-byte datagrams, reassembled, authenticated, and journaled before `receive()` returns. `prepare()` journals local evidence and persists its receipt before making a retransmittable datagram set. `transmit_reliably()` uses stop-and-wait: it sends those exact bytes at most four times, each with the admitted timeout (positive and at most five seconds), until it receives a fresh-channel, direction-keyed ACK for that sequence. Re-sealing the same sequence is disallowed.

The receiver sends an ACK only after both the journal append and external receipt sync succeed. It recognizes at most four recent authenticated packet identities and re-ACKs their duplicate fragments without delivering or journaling them twice. An ACK write failure does not suppress a frame that was already made durable; a later retransmission can obtain another ACK. While waiting for an ACK, a peer journals incoming evidence and queues at most eight frames for a later `receive()`. Timeout is ambiguous: the remote peer may have accepted the evidence even when all four ACK waits expire. The caller must reconcile retained receipts rather than infer rejection or send a new conflicting packet.

`ReceiptFiles` writes one synced file per journal receipt outside the journal. This is a **test harness artifact**, not an independently trusted rollback anchor: a party able to roll back both files can still hide a complete suffix. Before a real reconnect, an independent peer or ledger must supply the latest trusted receipt to `DurableSession::restore`. The transport never restores an old AEAD channel; it requires a new handshake and fresh keys. A persistence failure closes the transport handle before it sends or returns evidence.

The focused tests exercise a two-peer certificate/reveal exchange through loopback UDP, dropped data and ACKs, exact retransmission, ACK-send failure after persistence, out-of-order and duplicate fragments for a twelve-participant certificate, bounded retry exhaustion, and journal restore with fresh keys that reject stale ACKs and ciphertext. This slice has no NAT traversal, peer discovery, deadline consensus, execution proof, or ledger settlement. Real-value admission remains disabled until the full proof and validator qualification gates pass.
