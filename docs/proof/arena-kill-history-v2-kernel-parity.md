# Arena kill-history V2 kernel parity fixture

[`arena_kill_history_v2_parity.rs`](../../crates/arena-core/tests/arena_kill_history_v2_parity.rs) independently replays the exact unregistered Iroha research scene in `arena-core`: three FFA samurai on map 0 (Nyaagyu Estate), two Arc carbines, 1,000 atomic-unit bonds, 26 ticks, and shots at ticks 0, 12, and 24. The final tick is an admitted idle control, not unexecuted padding. Since first-release-7 the FFA spawns come from the arena data and are walled off from each other, so the scene places its players explicitly: slot 2 on the Control centre (0, 0), slot 0 at (0, -6000) aiming +y (yaw 16384) and slot 1 at (-6000, 0) aiming +x (yaw 0), both along clear lines. The story is unchanged: slot 1 kills slot 2 on tick 24 with slot 0 assisting, for awards of 20 and 80 and final allocations 1020, 1080 and 900; the terminal tick now also records the `MatchWinner` (slot 1).

The committed [JSON projection](../../crates/arena-core/tests/data/arena_kill_history_v2_kernel.json) contains all 27 tick-boundary fields used by Iroha's `KillResearchStateV1`, all 13 two-tick control batches in canonical wire hex, ordered events, final allocations, and full kernel state hashes. `kernel_revision` is the SHA-256 fingerprint of length-framed `lib.rs`, `simulation.rs`, `simulation/abilities.rs`, `simulation/hazards.rs`, `simulation/objectives.rs`, `simulation/respawn.rs`, `maps.rs`, `catalog.rs`, `math.rs`, `economy.rs`, and `protocol.rs`; it is a source-change tripwire, not an executable attestation or production proof identity. The test's `KERNEL_SOURCES` lists those hashed files and `NON_SIMULATION_SOURCES` lists the arena JSON export, transport, handshake, rollback, recovery, and `#[cfg(test)]` oracle files outside the kernel's dependency closure. `kernel_revision_classifies_every_arena_core_source` fails when any file under `crates/arena-core/src` is in neither list, when a hashed file uses an excluded module as a path, or when a hashed file compiles an excluded file through `#[path]` outside `#[cfg(test)]`. Splitting or adding a kernel module therefore requires an explicit classification and, for kernel files, a reviewed fixture regeneration.

Run the focused regression with `cargo test --locked -p arena-core --test arena_kill_history_v2_parity`. The test compares the live replay to every committed JSON value and explicitly checks the death, 20/80 awards, final idle-tick respawn countdown, and terminal state. A kernel change requires reviewing the resulting diff against Iroha's proof relation before regenerating the fixture with `ARENA_REGENERATE_KILL_V2_FIXTURE=1 cargo test --locked -p arena-core --test arena_kill_history_v2_parity`.

This fixture authenticates no wallet, admission, signed P2P certificate, ledger-selected history, or settlement. It does not qualify value-bearing play.
