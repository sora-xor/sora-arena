# Estate Lumen-card diagnostic (source only)

This tests one cause of the [packaged Mac entrance Surface Cache gaps](../../../docs/render-qualification/estate-ue583-m1-20260924/README.md): whether the two complex combined building meshes have too few generated Lumen cards. It is an experiment, not a coverage fix or release qualification. Epic's [UE 5.8 Lumen guidance](https://dev.epicgames.com/documentation/unreal-engine/lumen-technical-details-in-unreal-engine) states that the default is 12 cards per mesh; pink means uncovered Surface Cache and complex meshes may need more cards or separate parts.

Run only after the current owner releases the isolated UE **5.8.3** diagnostic Git worktree. The project release remains pinned to **5.8.2**. Do not run the importer in the main checkout. Keep the seven original screenshots in `docs/render-qualification/estate-ue583-m1-20260924/` as separate baseline evidence. A prior attempt to compare the release original directly with a 32-card duplicate failed: Unreal rebuilt the duplicate from 14,966 to 14,884 LOD0 triangles. Its raw logs and the stop decision are archived in `docs/render-qualification/estate-lumen-cards32-ue583-m1-20260924/`.

1. From the diagnostic project, run `scripts/unreal/diagnostics/import_lumen_cards32_art_review.py` through `UnrealEditor-Cmd -ExecutePythonScript=...`. The script requires UE 5.8.3 and a Git worktree. For each original building, it duplicates the asset twice under `/Game/Generated/Environment/ArtReview/Diagnostics/LumenCards32`, calls `StaticMeshEditorSubsystem.set_lod_build_settings` on **both** with 12 and 32 LOD0 cards, saves both, then requires exact equality between the clones for triangles, ordered material bindings, all Nanite settings, and numeric mesh bounds. It also checks that every other LOD0 build setting agrees and the original `.uasset` hash and mesh signature remain unchanged. Require two `SORA_LUMEN_CARDS_PAIRED_READY` log lines and four `SORA_LUMEN_CARDS_REBUILT` lines, with no Python errors. UnrealEditor-Cmd can exit 0 even when the Python script raises; do not rely on its exit code alone.
2. In a fresh editor process, run `scripts/unreal/diagnostics/validate_lumen_cards_pair.py` to reload the four saved ArtReview assets and repeat those checks before package work. Require two `SORA_LUMEN_CARDS_PAIRED_READBACK_READY` markers and no Python errors. If any geometry/material/Nanite/bounds gate fails, archive the logs, stop, and do not apply the runtime patch or package. The revised paired probe on 24 September 2026 failed at the Dojo: its 12-card clone still read 14,966 triangles while the 32-card clone read 14,884, with different bounds; independent reload confirmed the mismatch. See the archived paired-probe report in `docs/render-qualification/estate-lumen-cards32-ue583-m1-20260924/`.
3. Only if that gate passes and free disk remains safely above 30 GiB, confirm `git apply --check scripts/unreal/diagnostics/lumen_cards32_runtime.patch`, then apply it in the isolated checkout. The patch adds non-Shipping `-SoraReviewLumenCards12Rebuilt` and `-SoraReviewLumenCards32Rebuilt` selectors in `ImportedProp` for these two building names only. Both flags together are rejected. The selector changes only the asset path; existing material assignment, transform, shadow, distance-field flags, no-collision setup, and campaign blockout colliders stay the same. A missing duplicate is an error, not an implicit fallback to the original. Reverse the patch with `git apply -R` after capture.
4. Build, cook, and stage one Mac Development package containing both variants while keeping at least 20 GiB free. Run the **same package** at the verified fixed entrance camera with `-SoraArtReview`, once with `-SoraReviewLumenCards12Rebuilt` and once with `-SoraReviewLumenCards32Rebuilt`. Capture unedited `r.Lumen.Visualize 5` Surface Cache, `r.Lumen.Visualize.CardPlacement 1`, `r.Lumen.Visualize 3` Lumen Scene, and lit views at identical resolution and settings. Require ten `SORA_LUMEN_CARDS_REBUILT_SELECTED: cards=12` and ten `cards=32` lines respectively, matching all six Dojo and four Kura instances. Check for missing-asset, shader, and cook errors.
5. Archive both unedited 1280×720 Surface Cache PNGs. Run `python3 scripts/unreal/diagnostics/compare_lumen_roof_pink.py BASELINE.png CANDIDATE.png` to count magenta pixels separately in left `(135,250)–(280,320)` and right `(1000,250)–(1145,320)` roof/eave rectangles. The script reports each PNG hash and the pink count outside those rectangles too, so the lamp-top and foliage gaps stay visible as controls. Its `--self-check` mode confirms that the fixed rectangles and color threshold count 475 left and 512 right pink pixels in the archived original frame. Compare Card Placement and Lumen Scene with the full raw frames; a lower roof count would support the card-budget hypothesis, while unchanged pink would point toward the one-sided roof sheets and building mesh composition. Counts alone do not establish GI quality. Record frame time separately from visual coverage. Do not hide the visualization or change scalability to make the candidate appear to pass.

No production `SoraWorldBuilder.cpp` edit is part of this source-only diagnostic. The ArtReview duplicates have no automatic placement or gameplay effect. The source roof meshes remain unchanged; a later separate roof/body split with closed underlayment may be needed if this card-count probe fails.
