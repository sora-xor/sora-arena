# Estate Lumen-card diagnostic (source only)

This tests one cause of the [packaged Mac entrance Surface Cache gaps](../../../docs/render-qualification/estate-ue583-m1-20260924/README.md): whether the two complex combined building meshes have too few generated Lumen cards. It is an experiment, not a coverage fix or release qualification. Epic's [UE 5.8 Lumen guidance](https://dev.epicgames.com/documentation/unreal-engine/lumen-technical-details-in-unreal-engine) states that the default is 12 cards per mesh; pink means uncovered Surface Cache and complex meshes may need more cards or separate parts.

Run only after the current owner releases the isolated UE **5.8.3** diagnostic Git worktree. The project release remains pinned to **5.8.2**. Do not run the importer in the main checkout. Keep the seven original screenshots in `docs/render-qualification/estate-ue583-m1-20260924/` as the baseline evidence.

1. From the diagnostic project, run `scripts/unreal/diagnostics/import_lumen_cards32_art_review.py` through `UnrealEditor-Cmd -ExecutePythonScript=...`. The script requires UE 5.8.3 and a Git worktree. It verifies each original has 12 cards, duplicates `/Game/Generated/Environment/Props/SM_Nyaagyu_EstateDojo` and `SM_Nyaagyu_ProvisionKura` under `/Game/Generated/Environment/ArtReview/Diagnostics/LumenCards32`, sets **only** LOD0 `MaxLumenMeshCards` to 32 through `StaticMeshEditorSubsystem`, requests the rebuild, saves each duplicate, and checks readback, triangles, material slots, Nanite state, and the original `.uasset` hash. Require two `SORA_LUMEN_CARDS32_ART_REVIEW_READY` log lines.
2. In that same isolated checkout, confirm `git apply --check scripts/unreal/diagnostics/lumen_cards32_runtime.patch`, then apply it. The patch adds a non-Shipping `-SoraReviewLumenCards32` selector in `ImportedProp` for these two building names only. The usual path remains the original asset; the selector changes the asset path, while the existing material assignment, transform, shadow, distance-field flags, no-collision setup, and campaign blockout colliders stay the same. A missing duplicate is an error, not an implicit fallback to the original. The patch is diagnostic-only; reverse it with `git apply -R` after capture.
3. Build, cook, and stage one Mac Development package containing both variants. Run the **same package** at the verified fixed entrance camera with `-SoraArtReview`, first without and then with `-SoraReviewLumenCards32`. Capture unedited `r.Lumen.Visualize 5` Surface Cache, `r.Lumen.Visualize.CardPlacement 1`, `r.Lumen.Visualize 3` Lumen Scene, and lit views at identical resolution and settings. Require ten `SORA_LUMEN_CARDS32_SELECTED` lines in candidate logs, matching all six Dojo and four Kura instances; require none in baseline logs. Check for missing-asset, shader, and cook errors.
4. Archive both unedited 1280×720 Surface Cache PNGs. Run `python3 scripts/unreal/diagnostics/compare_lumen_roof_pink.py BASELINE.png CANDIDATE.png` to count magenta pixels separately in left `(135,250)–(280,320)` and right `(1000,250)–(1145,320)` roof/eave rectangles. The script reports each PNG hash and the pink count outside those rectangles too, so the lamp-top and foliage gaps stay visible as controls. Its `--self-check` mode confirms that the fixed rectangles and color threshold count 475 left and 512 right pink pixels in the archived original frame. Compare Card Placement and Lumen Scene with the full raw frames; a lower roof count would support the card-budget hypothesis, while unchanged pink would point toward the one-sided roof sheets and building mesh composition. Counts alone do not establish GI quality. Record frame time separately from visual coverage. Do not hide the visualization or change scalability to make the candidate appear to pass.

No production `SoraWorldBuilder.cpp` edit is part of this source-only diagnostic. The ArtReview duplicates have no automatic placement or gameplay effect. The source roof meshes remain unchanged; a later separate roof/body split with closed underlayment may be needed if this card-count probe fails.
